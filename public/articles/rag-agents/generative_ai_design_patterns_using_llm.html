Reason to Apply Design Patterns to large language models (LLMs)

Versatile and Adaptable

Large Language Models (LLMs) are an evolving AI technology with a broad set of use cases it can apply to. As a result, this powerful tool opens up a number of design patterns — from simple to complex — that can be leveraged to integrate LLMs seamlessly into existing architectures, broadening their applications and impact.

Design Patterns for “Simple Difficult” Use cases.

Use LLM Endpoint with Zero or Few Shot Learning

Use Cases

Code generation, Idea generation/brainstorming, Copywriting/content creation, General knowledge discovery/search, Basic translation/NLP tasks.

Descriptions

  • Empowering users with AI: Large language models (LLMs) can be used to improve productivity by allowing users to interact with them directly through prompts. These prompts can include text, code snippets, and other examples.
  • Without IT investment to implement use case, use this pattern to generate and transform language artefacts (code, text)
  • The simplicity and versatility of this design pattern — a general purpose natural language generation tool — makes it high value in complementing workflows of language and software production.

Challenges or Risk

  • There’s a risk that the content produced by LLMs may be inaccurate or biased.
  • To mitigate this, human experts should review the AI-generated content before it’s used.
  • Be mindful of the privacy risks associated with sharing confidential information or intellectual property (IP) with LLMs

LLM Endpoint Integration with Application

Use Cases

Empower your workforce with a secure LLM ecosystem. This fosters innovation through controlled access to code generation, idea brainstorming, content creation, knowledge discovery, and basic NLP tasks — all the benefits of as-is LLM utilization, delivered in a safe and managed environment.

Descriptions

  • Unleash the power of AI for content creation. This reframes the idea of using an LLM as a tool to boost creative output, rather than just a content generation tool. Easier to monitor compliance by recording usage via the proprietary user interface.
  • Secure your AI advantage. This sounds more intriguing than just mentioning control and security. It implies that using a well-managed LLM can provide a competitive advantage. Service called via API and results presented in UI frame inside host application. Takes advantage of the better privacy and security protections included in API offerings (as compared to the end-user applications).
  • APIs give more flexibility for creating complex workflows (for example, adding automated controls before sending data to the API)

Challenges or Risk

API costs require strategic oversight for optimal value. The emergence of vendor-provided private LLM instances may disrupt current cost-benefit models, necessitating a reevaluation of in-house user interface development.

Design Patterns for “Medium Difficult” Use cases.

Embed LLM Into an Application Workflow

Use Cases

  • LLMs Supercharge Productivity Tools: Imagine embedding LLMs into productivity software or collaboration tools. This empowers users with real-time insights, enhanced automation, and smarter workflows.
  • AI-Powered Search: LLMs can revolutionize search experiences by presenting relevant LLM outputs alongside existing search results, providing users with a richer tapestry of information.
  • Content Creation Revolution: Integrate LLMs seamlessly into content management systems. This opens doors for streamlined content creation, intelligent editing, and personalized recommendations.
  • Evolving Virtual Assistants: Chatbot applications can leverage LLMs to expand virtual assistant networks. This fosters natural language interactions and unlocks a new level of user support.

Descriptions

Integrating Large Language Models (LLMs) into Applications

  • This approach goes beyond simply exposing LLM APIs (like the Application Frame pattern) by embedding the LLM directly into a broader application workflow. This allows for deeper integration and leverages the LLM’s capabilities within the application itself.
  • The application calls the LLM through an API, then processes the results for use within the application.Enhances the functionality of an application.The application proactively queries the LLM for supplementary content to present to the user.
  • The LLM output directly influences another process within the application, potentially without displaying results in the user interface.

Challenges or Risk

Cost Optimization: To ensure fiscal responsibility, robust usage controls must be implemented to effectively manage LLM API costs. This ensures optimal resource allocation and long-term value.

Risk Mitigation: For certain use cases, direct integration of an LLM might pose potential risks. To address this, the development of comprehensive safeguards becomes crucial. This proactive approach ensures a controlled and secure environment for LLM implementation.

LLM used as Secondary Conversational Interface or Chatbot

Use Cases

  • Improving customer service chatbots
  • Augmenting nonplayable characters in video games

Descriptions

Hybrid Chat System: Seamlessly route user queries between chatbots and LLMs for broader knowledge and open-ended conversations.Existing chatbots integrate LLM access, either through orchestration or by intelligently handing off queries. This design brings unmatched Conversational Power via LLM.

Two Smart Handovers:

  • Orchestrator: A central system directs inquiries to the best resource, chatbot or LLM.
  • Low Confidence Fallback: Existing chatbots hand off complex questions to the LLM when unsure.

Challenges or Risk

  • Inconsistent Tone: LLM responses might clash with existing chatbot’s personality.
  • Accuracy Concerns: Potential for LLM errors or misleading information.
  • Privacy Risk: Sharing user data with external LLMs could be a privacy concern.

Design Patterns for “Complex” Use cases.

Document Retrieval or Search using LLM endpoint and Vector Databases

Use Cases

  • Using LLMs for Internal Document Databases: Leveraging LLMs to answer questions related to internal, private document databases.
  • Augmenting LLMs with Web Search Results: Enhancing LLMs by incorporating web search results.

Description

A search or retrieval model integrates relevant documents into the context of an LLM prompt. It relies on a search engine or retrieval system. this enhances the LLM response by incorporating specific, previously unseen documents, including recent knowledge and internal data.It provide solution architecture with an additional retrieval or search model, which must be obtained or developed separately. The retrieval/search model can utilize vector databases or other indexed knowledge bases. Its implementation combines two established models — large language models and search — allowing for their joint use.

Potential : By integrating LLMs with internal document databases, we can unlock insights from internal data using LLM capabilities.

  • Access to more accurate and recent information.
  • Possibility of including references or citations to the original source documents in the generated responses.

Challenges or Risk

  • LLM retrieval models may still be inaccurate and prone to hallucinations, although typically less so than when using LLMs without retrieval.
  • Requires robust information classification to address privacy risks.
  • Data leakage risk if LLM and search components are not part of the same infrastructure.

Next Generation LLM Agents

Use Cases

Personal Assistants Based on LLM Technologies:

  • These assistants leverage large language models (LLMs) to enhance their capabilities.
  • They can handle a wide range of tasks, from answering questions to providing recommendations.

Sophisticated Chatbots with LLMs:

  • Incorporating LLMs allows chatbots to understand context, generate more natural responses, and adapt to user input.

Task-Specific Enterprise Assistants: These specialized assistants cater to specific business functions:

  • CRM : Managing customer relationships and interactions.
  • Procurement : Streamlining purchasing processes.
  • HR : Handling employee-related tasks.
  • Banking : Assisting with financial transactions and inquiries.

Description

  • Description : An agent performs iterative and autonomous calls to the LLM API and other models/tools to achieve user tasks.Some tasks demand flexibility beyond fixed workflows, adapting to user input. Recursive access to LLMs and other tools enables this adaptability. A central “task planning and model selection” model recursively calls various APIs, retains interaction history, and generates responses. This model could be an LLM or have a distinct architecture.Open-source models facilitate building such agents. LLM agents are emerging, each with varying degrees of success.
  • The system has the potential to perform tasks on behalf of users.This capability streamlines user interactions and automates processes.
  • Beyond simple actions, the system can tackle complex user requests. It adapts to various scenarios, enhancing user experience.
  • Due to its recurring nature, the system can self-correct.It learns from past interactions and improves over time.

Challenges or Risk

  • The combined system’s ability to execute actions introduces security risks.
  • However, implementing this capability is currently technically challenging and unfeasible for most use cases.
