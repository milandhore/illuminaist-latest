This demo provides a secure and practical way to explore OpenClaw Finance using locally hosted Ollama models. It allows users to experiment with finance-related data and workflows in a controlled environment.

By working with simulated, finance-style datasets, you can understand how OpenClaw operates without any risk to real banking systems or sensitive information. This makes it an ideal starting point for beginners, developers, and anyone looking to safely test and learn before moving to real-world financial applications.

Getting Started with OpenClaw Finance Using Ollama

What This Demo Includes

  • transactions.csv: sample bank-like transaction data
  • prompts.md: prompts to run in the OpenClaw dashboard
  • finance-demo-skill/SKILL.md: a minimal skill for local finance analysis

What You Will Build

You will run:

  • Ollama as the local model runtime
  • OpenClaw as the agent and dashboard
  • a local finance demo using a sample CSV instead of a real bank connection

This is the right first step for banking and finance experiments because it lets you verify:

  • model quality
  • tool behavior
  • prompt structure
  • file handling
  • report generation

without giving the agent real credentials or live money movement capability.

Recommended Setup

  • Use Ollama for the model provider
  • Use OpenClaw with a local gateway
  • Start in the browser dashboard, not a messaging channel
  • Use fake or sanitized transaction data first

Step 0: Check Prerequisites

OpenClaw currently requires Node 22+.

Check Node:

node --version

If you do not have Node installed, the OpenClaw installer can install it for you.

Step 1: Install Ollama

Official Ollama install options:

  • macOS: download the app from https://ollama.com/download
  • Windows: use the installer from https://ollama.com/download/windows
  • Linux: use the install script below

Linux install command:

curl -fsSL https://ollama.com/install.sh | sh

Verify the CLI:

ollama --version

Step 2: Start Ollama and Pull a Model

If you are on macOS or Windows and installed the app, Ollama usually starts its local server automatically.

On Linux, or if you want to run the server manually:

ollama serve

OpenClaw’s official Ollama provider docs recommend tool-capable models such as:

  • gpt-oss:20b
  • llama3.3
  • qwen2.5-coder:32b
  • deepseek-r1:32b

For a first finance demo, start with one of these:

ollama pull gpt-oss:20b
ollama pull llama3.3

Verify the model is installed:

ollama list

Verify the local API is reachable:

curl http://localhost:11434/api/tags

Step 3: Install OpenClaw

Install the CLI with the official installer:

curl -fsSL https://openclaw.ai/install.sh | bash

Verify the CLI:

openclaw --help

Step 4: Enable Ollama for OpenClaw

OpenClaw’s Ollama docs say the simplest path is implicit discovery.You do not “get” OLLAMA_API_KEY from anywhere. For OpenClaw’s Ollama integration, you just set it yourself to the literal value ollama-local.

Set this environment variable:

export OLLAMA_API_KEY="ollama-local"

This is not a real secret. It is just the opt-in switch OpenClaw uses to enable local Ollama model discovery.

If you want it to persist in zsh, add it to your shell profile:

echo 'export OLLAMA_API_KEY="ollama-local"' >> ~/.zshrc
source ~/.zshrc

Step 5: Run OpenClaw Onboarding

Run:

openclaw onboard --install-daemon

Use these choices:

  • Setup: QuickStart
  • Gateway mode: Local gateway
  • Workspace: default is fine unless you want a dedicated finance workspace
  • Channels: skip them for now
  • Daemon install: yes

If the wizard asks you to choose a model and your Ollama models are already discovered, pick one like:

  • ollama/gpt-oss:20b
  • ollama/llama3.3

If the wizard does not show your Ollama model, finish onboarding first, then use the checks in Step 6.

Step 6: Verify OpenClaw Sees Ollama

Run these checks:

openclaw gateway status
openclaw models list
openclaw models status

You should see an ollama/... model in the output.

If you do not, check:

  • OLLAMA_API_KEY is set in the same shell session
  • ollama serve is running or the app is active
  • the model is installed in ollama list

Step 7: Open the Dashboard

Run:

openclaw dashboard

This is the fastest first chat path and avoids unnecessary channel setup.

Step 8: Copy the Sample Finance Data Into the OpenClaw Workspace

Please feel free to use any data .Its not tied with data .Find your workspace:

openclaw config get agents.defaults.workspace

Copy the sample CSV:

cp examples/openclaw-finance-demo/transactions.csv "$(openclaw config get workspace)/transactions.csv"

Step 9: Add the Finance Demo Skill

Create the skill directory and copy the skill file:

mkdir -p "$(openclaw config get workspace)/skills/finance-demo"
cp examples/openclaw-finance-demo/finance-demo-skill/SKILL.md "$(openclaw config get workspace)/skills/finance-demo/SKILL.md"

Start a new dashboard session after copying the skill so the agent picks it up cleanly.

Step 10: Run the Banking and Finance Demo

Open prompts.md and paste the prompts into the OpenClaw dashboard one by one.

Start with:

Analyze transactions.csv and summarize total income, total expenses, and net cash flow for March 2026.

Then continue with:

  • category analysis
  • subscription detection
  • anomaly detection
  • budget planning
  • report creation

Step 11: Ask OpenClaw to Produce Files

Once the CSV analysis works, use a file-producing prompt such as:

Create a file named budget-report.md with total income, total expenses, net savings, largest spending categories, and 3 practical budget recommendations.

This is useful because it confirms the agent can:

  • read local files
  • reason over structured finance data
  • produce a reusable report in the workspace

Optional: Set the Default Model Explicitly

If you want to force a specific Ollama model as the OpenClaw default, set it in config or use the model command in chat.

Example config snippet:

{
"agents": {
"defaults": {
"model": {
"primary": "ollama/gpt-oss:20b",
"fallbacks": ["ollama/llama3.3"]
}
}
}
}

If you manually define models.providers.ollama, use the native Ollama base URL without /v1.

Use:

http://host:11434

Do not use:

http://host:11434/v1

The OpenClaw Ollama provider docs explicitly warn that /v1 can break tool calling.

Optional: Fast Shortcut from Ollama

Ollama’s own quickstart docs also list:

ollama launch openclaw

Use that if you want a shortcut entry point from Ollama itself. For learning and troubleshooting, the manual OpenClaw setup in this guide is better because you can verify each layer separately.

Common Problems

OpenClaw shows no Ollama models

Check:

echo "$OLLAMA_API_KEY"
ollama list
curl http://localhost:11434/api/tags
openclaw models list

If ollama list works but openclaw models list does not show anything, your model may not be auto-discovered as tool-capable. In that case, pull one of the officially suggested models such as gpt-oss:20b or llama3.3.

The model is too slow

Try a smaller Ollama model that still supports tools, or move to a machine with more RAM or GPU capacity. OpenClaw’s FAQ warns that weaker local models are more vulnerable to prompt injection, so keep tool access narrow if you use a smaller model.

The dashboard opens but answers are poor

This is usually a model-quality issue, not an OpenClaw issue. Switch to a stronger model first, then re-test the same prompt.

I want to connect a real bank

Do not start there. First prove that:

  • the model can read and analyze CSV exports accurately
  • the skill instructions work
  • the model behaves safely around finance prompts

Then move to read-only APIs or sanitized exports. Avoid giving OpenClaw payment or transfer permissions during early experiments.

Suggested Learning Path After This Demo

  • Replace transactions.csv with your own sanitized export
  • Add a second month and ask for trend analysis
  • Create prompts for fraud-like anomaly review
  • Add a read-only integration later if you still need live data

Safety Notes

  • Use fake or sanitized data first.
  • Do not give the agent real bank credentials in chat.
  • Prefer CSV import or read-only APIs over direct transaction execution.
  • Keep finance work in a separate OpenClaw workspace from your normal experiments.
  • If you use a smaller local model, restrict tools and treat results as less trustworthy.
