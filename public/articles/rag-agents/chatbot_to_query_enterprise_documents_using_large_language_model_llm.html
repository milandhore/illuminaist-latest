Enterprise Document Repository

An enterprise document repository is a system for storing, organizing, and managing electronic documents. It is typically used by large organizations to store a wide variety of documents, such as contracts, financial records, customer data, and product specifications. Your internal knowledge base documents in a format suitable for querying.

Example: Microsoft SharePoint, Google Workspace, Box, Dropbox Business, IBM FileNet, DocuWare

Embeddings via Embedding Model

Embeddings are a key component of large language models (LLMs). They are used to represent words and phrases in a way that computers can process — as vectors, or N-dimensional arrays, of numbers. These numerical vectors capture the meaning of words by representing different characteristics of a word with numbers in an array.

In this step, Embed the text chunks using an embedding model. This transforms each chunk of text into a numerical representation that captures its essence.

Example: Word2Vec, OpenAI Embedding Model (via Subscription only) , BERT, Node2Vec

Vector Database

Vector databases are important because they provide a way to efficiently store and query vector data. Vector data is a type of data that is represented as a vector, or a multidimensional array of numbers. Vector data is commonly used in machine learning applications, such as natural language processing (NLP), computer vision, and recommendation systems.

Store the vector embeddings in a vector database. This database will serve as the repository for your encoded knowledge base.

Examples: AWS OpenSearch, Azure Cognitive Search, Pinecone, Milvus, Weaviate, Faiss

Vector Indexing

Approximate nearest neighbor (ANN) search is a technique for finding the closest points to a query point in a high-dimensional space. ANN search is often used in machine learning applications, such as natural language processing, computer vision, and recommendation systems.ANN search algorithms are designed to be fast and efficient, even when dealing with large datasets and complex feature spaces. However, ANN search algorithms typically trade accuracy for speed. This means that the results of an ANN search may not be as accurate as the results of an exhaustive search. Index the vector embeddings using an approximate nearest neighbor (ANN) search algorithm. This will allow you to quickly find the most similar vectors to a given query.

Online Process to Submit User Query via Chatbot

Build a chatbot using an LLM. The LLM will be used to generate answers to user queries by retrieving relevant information from the vector database. Connect the chatbot to the vector database. This can be done using a REST API or another communication protocol.

Deploy the chatbot to a production environment. This can involve making it available through a website, mobile app, or other channel. Once the chatbot is deployed, users can interact with it by asking questions in natural language. The chatbot will use the LLM to generate answers by retrieving relevant information from the vector database.

Here is an example of how the chatbot would work:

  • User : Where can find good Strategic Articles?
  • Chatbot : You can find good strategic Articles on Milan’s Outlook.

The chatbot would first retrieve the vector embedding for the query “Where can find good Strategic Articles?”. Then, it would use the ANN search algorithm to find the most similar vector embeddings in the vector database. These embeddings would correspond to articles, blog posts, or FAQs about the good strategic Articles. The chatbot would then use the LLM to generate an answer based on this information.

LLM-based chatbots can be a powerful way to query enterprise knowledge bases. They can provide users with quick and accurate answers to their questions, even if they are complex or open-ended.

Please note that the diagram in the image is a simplified representation of the process. In practice, there are a number of additional factors to consider, such as the specific LLM that is used, the way that the knowledge base is structured, and the security and performance requirements of the chatbot.

Offline Process (In-Short)

  • The user ingests enterprise documents.
  • The query is sent to an embedding model, which generates a vector representation of the query.
  • The vector representation of the query is compared to the vector representations of all documents in the enterprise document repository.
  • The documents with the most similar vector representations to the query are retrieved.

Online Process (In-Short)

  • The user enters a query.
  • The query is sent to a large language model (LLM) embedding model.
  • The LLM generates a vector representation of the query.
  • The vector representation of the query is compared to the vector representations of all documents in the vector database.
  • The documents with the most similar vector representations to the query are retrieved.

Key differences between the offline and online processes:

  • The offline process is a batch process, meaning that it is performed periodically on the entire document repository. The online process is a real-time process, meaning that it is performed on demand for each user query.
  • The offline process uses a vector indexing algorithm to find the most similar documents to the query. The online process uses a nearest-neighbor search algorithm to find the most similar documents to the query.
